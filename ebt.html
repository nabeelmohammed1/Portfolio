Everything but Titans is a fast-paced, shooter prototype inspired by the fast-paced "jetpack" eras of classic FPS titles. Designed from the ground up for both single-player and fully replicated multiplayer, this project served as a deep dive into advanced Unreal Engine frameworks, low-level C++ architecture, and real-world networking.

Technical Architecture

Advanced GAS via Custom C++: By building custom Abilities and intricate Gameplay Cues, I created a highly scalable framework. This allowed me to push GAS to its limits, turning complex mechanics like jetpack jumping, momentum-based dashes, and more into modular, data-driven assets that could be endlessly combined and iterated upon without bloating the codebase. Overall for this prototype, I architected 10 different movement/combat abilities for players to use.

Server Logic: To move beyond simple LAN testing, I integrated the Steam SDK (Steamworks) to handle session creation, matchmaking, and live player connections. I conducted extensive research into server-authoritative architecture to ensure fairness in a high-mobility environment.

Replication: By using GAS's built-in client-side prediction, I ensured that high-speed aerial combat felt instantly responsive for the client while remaining perfectly synchronized across the Steam network. I created custom functions that help the clients update the server with the player's locations when they grappled/dashed as the speed the players moved at caused hiccups with the server/client synchronization.

AI Research: For the enemy bots, I explicitly chose to experiment with Unreal's newer State Tree system over traditional Behavior Trees. Through my research, I determined that while Behavior Trees are excellent for complex, long-term hierarchical tasks, State Trees provide a much tighter, highly optimized state-machine structure.

Technical Challenges & Solutions

1

Challenge: Creating the “Feel” of Combat

Because aerial mobility is the defining pillar of a jetpack shooter, establishing tight, precise, and momentum-driven traversal mechanics was absolutely critical to the game's core loop.

Solution

By centralizing movement and combat logic within my C++ GAS framework, I established a highly modular environment for rapid iteration. This data-driven approach allowed me to continuously tweak exposed parameters like gravity scaling, thrust velocity, and air-strafing in real-time, enabling rapid fine-tuning until the aerial combat felt fluid, responsive, and highly rewarding.

Challenge: Replication

A major technical hurdle was mitigating server-client latency and resolving timing discrepancies to ensure high-speed aerial movement felt responsive in a multiplayer environment without rubber-banding.

Solution

To bridge this gap, I deeply leveraged the prediction architecture of the Unreal Engine Gameplay Ability System (GAS). Instead of waiting for server authority, I configured client-side prediction for all traversal abilities. The local client immediately executes the movement while simultaneously sending RPCs for background server validation. By engineering custom C++ logic to fine-tune how Target Data and state variables replicate, I successfully masked network latency, achieving seamless, authoritative, lag-free aerial combat.

Behavior Tree VS State Trees

For the enemy bots in this project, I explicitly chose to build their logic using Unreal's State Tree system instead of the traditional Behavior Trees I normally use. My goal was to force myself out of my comfort zone and see how this newer framework handled the fast-paced, reaction-heavy AI required for a shooter.

Data Binding vs. Blackboards Switching from Behavior Trees gave me deep insight into State Tree property binding. I learned how to architect strict, state-driven logic, making it easier to manage complex combat phases without relying on tangled, Blackboard variables.

Explicit States Stepping out of my comfort zone revealed how State Trees excel at managing highly specific scenarios. I learned that explicitly defining states, like evasive dashing, provided a more scalable way to build AI capable of tracking omni-directional movement.

Balancing Visibility with Performance This technical experiment highlighted the difference between visual debugging and execution speed. I discovered that although Behavior Trees provide a top-down flow for catching logic errors, State Trees strip away that heavy overhead, offering the raw speed necessary for fast-twitch enemy AI.
